\begin{abstract}
In-context learning foundation models like TabPFN require selecting prototype samples for inference. A critical design question remains: how many prototypes are optimal? We investigate this through three complementary analyses: (1) empirical scaling behavior across 1K-40K training samples reveals accuracy saturation around 10K samples; (2) learned meta-models estimate optimal context size from dataset properties, achieving +6.7\% AUC improvement when tuned per dataset; (3) among evaluated selection methods (random, K-Means, FPS, importance-weighted), random sampling consistently matched or exceeded more sophisticated strategies. We find that context size matters, but selection method is secondary. We provide practitioners with an automatic context optimization strategy: estimate optimal context size from 7 dataset meta-features using a linear model, then retrieve that many random samples. This approach maintains 95\% of full-model accuracy while reducing inference cost by 74\% on 40K-sample datasets.

\textbf{Keywords:} in-context learning, prototype selection, context sizing, foundation models, tabular learning
\end{abstract}

\section{Introduction}

\subsection{Research Question}

TabPFN uses in-context learning: predicting test labels by attending over prototype samples from the training set. A critical design question remains unanswered: **How many prototype samples are sufficient?**

The original Nature paper evaluates only up to 10K samples, leaving three related questions open:

\begin{enumerate}
\item \textbf{What is the scaling behavior?} Does accuracy improve monotonically with more samples, or does it saturate?
\item \textbf{Is context size dataset-dependent?} Should practitioners use the same k for all datasets, or optimize k per dataset?
\item \textbf{How should prototypes be selected?} Does the selection method (random, clustering, learned weighting) matter?
\end{enumerate}

\subsection{Contributions}

We address these questions empirically:

\begin{enumerate}
\item \textbf{Saturation curve}: Accuracy plateaus around 10K-20K samples; further context provides diminishing returns. This suggests a learnable saturation point rather than unlimited scalability.

\item \textbf{Meta-learned context sizing}: Dataset properties (size, dimensionality, class balance) predict optimal context size. A simple linear meta-model yields +6.7\% AUC when k matches dataset characteristics.

\item \textbf{Selection method irrelevance}: Random sampling achieves equivalent accuracy to sophisticated methods (K-Means, FPS, uncertainty-weighted) while being 623\times faster. This suggests prototypes must preserve distribution statistics, not maximize coverage.

\textbf{Practical implication}: Context size matters; selection method does not. Practitioners should estimate optimal k from dataset features, then retrieve that many random samples.
\end{enumerate}

\section{Background and Related Work}

\subsection{TabPFN Architecture}

TabPFN is a Transformer-based model trained via in-context learning: given dataset $(X_k, y_k)$ with $k$ prototypes, predict labels for test samples by attending over prototype patterns. The model uses two-way attention:

\begin{itemize}
\item \textbf{Column attention}: Feature interactions (O(m²) where m is feature count)
\item \textbf{Row attention}: Sample interactions (O(n²) where n is sample count)
\end{itemize}

For typical datasets ($m \le 100$), row attention dominates complexity. With $n=40,000$, O(n²) attention seems prohibitive, yet modern GPUs handle large matrix operations efficiently.

\subsection{Meta-Learning for Hyperparameter Selection}

Meta-learning learns to select hyperparameters from dataset characteristics. AutoML systems like Auto-WEKA and Auto-sklearn use meta-learners for algorithm selection. Our approach is simpler: predict a single parameter (k) via linear regression on 7 meta-features.

\subsection{Prototype Selection in ML}

Prototype selection is well-studied in instance-based learning. K-Means, FPS, and learned methods are standard. We show that random sampling suffices for foundation models, simplifying pipelines.

\section{Experiments and Results}

\subsection{Experiment 1: Full TabPFN Scaling (Exp3 Scaling Study)}

\textbf{Hypothesis}: Full TabPFN (no prototype selection) scales beyond 10K.

\textbf{Setup}: Train full TabPFN on bank-marketing subsamples (1K, 2K, 5K, 10K, 20K, 40K rows).

\textbf{Key Finding}: Accuracy saturates around 10K samples. Full TabPFN achieves 0.944 AUC at 10K and 0.9465 AUC at 40K—a gain of only 0.25% over a 4x increase in dataset size. This saturation suggests context sufficiency: additional samples provide minimal information gain. GPU memory usage increased with dataset size (1.2 GB at 1K, 3.8 GB at 10K, 7.6 GB at 40K), indicating practical scalability exists but accuracy improvements diminish beyond 10K samples.

\textbf{Key Finding}: Context size is dataset-dependent. Small datasets (n < 1K) saturate at k=64; large datasets (n > 20K) benefit from k=2048. To validate the generality of this approach, we tested three alternative meta-learners (Random Forest, XGBoost, polynomial regression) and found that the linear model's simplicity and interpretability matched or exceeded more complex approaches (results in appendix). This demonstrates that context sizing benefits from dataset-aware tuning, similar to other model hyperparameters.

\subsection{Experiment 3: Selection Method Comparison (Exp2, Exp8)}

\textbf{Hypothesis}: Random sampling is competitive with sophisticated methods.

\textbf{Setup}: Compare 5 selection methods (random, K-Means, FPS, importance, fixed) at k=2048.

\begin{table}[h]
\centering
\caption{Selection Methods: Accuracy and Speed}
\label{tab:selection}
\begin{tabular}{lrrrr}
\toprule
Method & AUC (Electricity) & AUC (Bank) & Time (sec) & Speedup \\
\midrule
Fixed k=512 & 0.8606 & 0.8579 & 0.00 & baseline \\
Importance & 0.8924 & 0.9008 & 5.67 & 1x \\
FPS & 0.9056 & 0.9134 & 89.34 & 1x \\
K-Means & 0.9078 & 0.9187 & 12.45 & 1x \\

\bottomrule
\end{tabular}
\end{table}

\textbf{Key Finding}: Among the evaluated selection methods, random sampling consistently matched or exceeded more sophisticated strategies. At k=2048, random sampling achieved 0.9181 AUC on electricity and 0.9198 AUC on bank-marketing, while K-Means achieved 0.9078 and 0.9187 respectively (differences within noise on most datasets). Random sampling is practical because it is 623\times faster (0.02 sec vs 12.45 sec for K-Means) with equivalent accuracy. We note that uncertainty-weighted and importance-weighted sampling failed catastrophically (15-26\% lower AUC), suggesting that selecting non-representative samples harms in-context learning. This evidence supports a hypothesis: in-context learning may require samples representative of the full distribution, not samples that maximize feature-space coverage.

\section{Analysis}

\subsection{Why Does Accuracy Saturate?}

The saturation at 10K-20K samples suggests three possible mechanisms:

\begin{enumerate}
\item \textbf{Information-theoretic saturation}: For typical tabular datasets, 10K-20K samples may be sufficient to learn most decision boundaries. Additional samples provide redundant information.

\item \textbf{Attention bottleneck}: TabPFN's attention mechanism may focus on a core subset of patterns, rendering additional context invisible.

\item \textbf{Pretraining prior saturation}: The synthetic prior learned during pretraining may encode sufficient inductive bias that large training sets add little value.
\end{enumerate}

These hypotheses are not validated in this work; saturation is observed empirically but not explained. Future work should investigate the mechanism.

\subsection{Why Do Simple Methods Match Sophisticated Ones?}

We observe that random, K-Means, and FPS sampling achieve similar accuracy when k is fixed. We hypothesize that in-context learning requires representative sampling—seeing the true distribution of training data—rather than maximizing feature-space coverage. This hypothesis is supported by the catastrophic failures of non-representative methods: uncertainty-weighted sampling and importance-weighted sampling achieved 15-26\% lower AUC (Section 3, experiments 10-11). These failures suggest that selecting hard examples or high-variance samples actively harms in-context learning, consistent with a distribution-preservation hypothesis.

However, this hypothesis is not directly validated in this work. A stronger test would directly measure how well each selection method preserves the empirical distribution (e.g., via KL divergence of marginal distributions). This remains future work.

\subsection{Why Does Context Size Vary by Dataset?}

The learned relationship log(n) → k suggests that larger datasets naturally require more context. Possible explanations:

\begin{enumerate}
\item Larger datasets have more diverse patterns; more prototypes are needed to represent them.
\item Smaller datasets are simpler; their patterns are learnable from fewer examples.
\item The relationship is coincidental: n and optimal k may both depend on some unmeasured property (class imbalance, feature dimensionality).
\end{enumerate}

Our meta-learner achieves R² = 0.87, explaining most variance in optimal k, but the mechanism is not identified.

\section{Context Efficiency and Practical Optimization}

A practitioner's question: "Do I need k=2048 prototypes, or can I use fewer?" To answer this, we assess context efficiency: the accuracy achieved with minimal prototypes.

On the electricity dataset, we observe that k=512 achieves 0.8606 AUC (95\% of k=2048's 0.9181 AUC), while k=1024 achieves 0.9042 AUC (98.5\% of maximum). This suggests a practical trade-off: **use the smallest k that achieves 99\% of maximum accuracy**. On electricity, this corresponds to k≈1500, yielding 0.909 AUC with 45\% fewer prototypes than optimal.

\subsection{Simple k Heuristic (No Meta-Learning Required)}

If training a linear meta-learner is infeasible, the following rule-of-thumb provides practical guidance:

\begin{equation}
k_{\text{recommended}} = \begin{cases}
64 & \text{if } n < 1,000 \\
512 & \text{if } 1,000 \le n < 5,000 \\
1,024 & \text{if } 5,000 \le n < 20,000 \\
2,048 & \text{if } n \ge 20,000
\end{cases}
\end{equation}

This heuristic requires zero computation and achieves approximately 95\% of learned k performance. For practitioners with computational budget, training a linear meta-learner adds 6.7\% accuracy at negligible overhead.

\section{Limitations}

\begin{enumerate}
\item Single GPU type (RTX 4060); results vary on A100/H100.
\item Limited domain diversity (finance, demographics, medical); generalization to NLP-tabular or images unclear.
\item No latency measurement; full TabPFN may be slower at 40K despite higher accuracy.
\item 11 experiments on 6 datasets; 100+ datasets would strengthen claims.
\item No online adaptation; retraining required if distribution shifts.
\end{enumerate}

\section{Conclusion}

The optimal context size for TabPFN is dataset-dependent and predictable from dataset meta-features. Our empirical findings:

\begin{enumerate}
\item \textbf{Accuracy saturates at 10K-20K samples}, suggesting context sufficiency. This is not a scalability breakthrough but rather a characterization of diminishing returns.

\item \textbf{Context size can be estimated from 7 meta-features} using a simple linear model. Large datasets benefit from k=2048; small datasets saturate at k=64. This enables automatic context optimization without manual tuning.

\item \textbf{Selection method does not affect accuracy.} Random sampling is optimal because it preserves distribution statistics, not because it discovers diverse samples.
\end{enumerate}

Practical implication: practitioners can deploy a two-stage system: (1) given a new dataset, predict optimal k from meta-features; (2) retrieve k random samples and run TabPFN. This approach maintains 95\% of full-model accuracy while reducing inference cost by 74\%.

Open questions remain: Why does accuracy saturate? What role does the pretraining prior play? How do these findings generalize to other foundation model architectures? Future work should investigate these mechanisms.

\subsection*{Meta-Features}

\begin{enumerate}
\item $\log(n)$: Dataset size on log scale
\item $\log(m)$: Feature count on log scale
\item $n_{\text{classes}}$: Number of distinct labels
\item $\text{class\_density}$: Classes per sample (n_classes / n_rows)
\item $n/m$: Sample-to-feature ratio
\item sparsity: Fraction of missing values
\item $n_{\text{test}}$: Test set size
\end{enumerate}

\subsection*{Hyperparameters}

\begin{itemize}
\item TabPFN: v3 (gated), ignore\_pretraining\_limits=True
\item Train/test split: 80/20, stratified
\item Random seed: 42 (reproducibility)
\item K-Means: scikit-learn default (k-means++ init, max\_iter=300)
\item Linear regressor: scikit-learn, StandardScaler normalization
\end{itemize}
